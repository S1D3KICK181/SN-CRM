Architecture

A separate backend—without
a dangerous big-bang rewrite.

UI
TanStack Start

Premium role-aware interface, typed queries, clear loading and error states.

Existing routes remain working while migration proceeds.
→
API
Practice API

Separate Node server, typed contract, validation, CORS, abort handling, and idempotent operations.

Dashboard and assignment transitions use the seam now.
→
DB
Repositories

Credential-free demo repository or Supabase repository preserving the user's token and RLS.

Same business contract, different data source.

Trust model

Security and financial integrity
are architectural, not decorative.

Row-level permission layer

Roles live in user_roles; security-definer helper functions govern visibility and involvement.

Privilege isolation

Founder-only operations verify the founder role before the service client is ever loaded.

Atomic business operations

Mutation, audit event, outbox event, and idempotency receipt commit as one transaction.

Derived financial truth

Allocation triggers own invoice received totals and paid status; UI code cannot forge them.

Concurrency safety

Expected versions and transaction advisory locks prevent stale or duplicate changes.

Deployment gate

The migration must be executed and validated on disposable or staging PostgreSQL before production.
